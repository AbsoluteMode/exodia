# Spec: API & Models — реестр ключей и модель на каждую AI-фичу

> Вкладка называется «API & Models» (решение Максима 19.10; раньше в обсуждении — «Keys & models»).

> Статус: реализовано в ветке `claude/keys-and-models` (19.10.2026), ждёт PR и приёмки на рабочем приложении.
> План — [docs/plans/api-and-models.md](../plans/api-and-models.md), решение —
> [2026-10-19-api-and-models](../../.project-docs/decisions/2026-10-19-api-and-models.md).
> Дополнение 19.10: Anthropic для строки Agent (Task 20), см. «Не цели v1».
> Спека писалась на `origin/main` 2a85e6d; реализация сверена с a316508 (PR #35).

## Что строим

Вкладку настроек **API & Models** вместо нынешней **Models**. В ней два блока:

1. **API keys** — ключи провайдеров для самого Whytap. Пользователь заводит их один раз.
2. **Models** — по строке на каждую AI-фичу. В строке одна выпадашка с моделью;
   провайдер виден в её названии («Soniox · stt-rt-v5»).

Whytap сам узнаёт у провайдера актуальный список моделей и решает, подходит ли
модель фиче. Неподходящая модель видна с пометкой «Not supported yet» и причиной.

## Зачем: что не так сейчас

Проверено по коду `origin/main` и по настройкам прода Максима 19.10.2026.

- **Ключи разбросаны.** Ключи транскрибации вводятся в карточке провайдера во
  вкладке Models (`SettingsModelsView`). Ключ OpenRouter вводится в двух местах:
  в Models (блок «Smart processing LLM») и в Agents (`AgentModeView`, подпись
  «The key is shared with Models»).
- **Один провайдер и одна модель транскрибации на всё.** `SelfKeyPreferences.selectedProvider`
  и `transcriptionModel(for:)` обслуживают Drop Fast и Smart, голос агента,
  голосовой поиск, митинги и запасную расшифровку Drop.
- **Одна LLM на Drop Smart и заметки митингов** (`llmLevel` + `openRouterModel`
  или свой сервер). У агента отдельная модель OpenRouter во вкладке Agents
  (`AgentSettingsStore.openCodeModel`).
- **Модели транскрибации вшиты в код.** Для real-time — по одной на провайдера
  (`BYOKProvider.availableTranscriptionModels`). Для записи — константы:
  `SonioxFileAPI.asyncModel = "stt-async-v5"`, `"scribe_v2"` в `ProviderBatchTranscriber`.
  Список с сервера подтягивается только у OpenRouter (`OpenRouterLLMClient.listModels`),
  и проверяется в нём одно: что модель отвечает текстом. Умеет ли модель
  инструменты (агенту это нужно), никто не проверяет.
- **Экран показывает не то, что уходит.** В проде у Максима сохранена Soniox
  `stt-rt-v4`. Вкладка Models показывает `stt-rt-v5`: в списке приложения одна
  модель, и `SettingsModelsView.modelField` рисует `models.first`. А
  `TranscriptionSessionFactory` отправляет сохранённую `stt-rt-v4`. Сейчас это
  безвредно: по документации Soniox `stt-rt-v4` с 30.06.2026 — устаревший
  псевдоним `stt-rt-v5`. Но когда псевдоним исчезнет, Drop сломается, а экран
  об этом не скажет.

## Решения Максима (не пересматривать)

1. Ключи — для самого Whytap. Case (сейф пользовательских ключей для агентов и
   команд) не трогаем.
2. Одна вкладка **API & Models** вместо Models, с двумя блоками: API keys и Models.
3. Компактный вид (макет 19.10, описан ниже):
   - API keys — ряд чипов с точкой статуса и чип «Add key»;
   - Models — строка на фичу и одна выпадашка модели;
   - отдельной выпадашки провайдера нет.
4. Уточнение 20.10: в свёрнутой строке видны название функции и краткая сводка
   выбранных моделей. Нажатие раскрывает меню прямо под строкой; одновременно
   открыта одна функция. Подписей real-time, recorded и LLM with tools нет.
   Внутренний режим по-прежнему фильтрует список подходящих моделей. Ошибки и
   действия исправления остаются видимыми без раскрытия.
5. Новые модели — вариант B. Модель, которой нет среди проверенных, становится
   доступна после автопроверки: сверки с данными провайдера и пробного запроса.
   Не прошла — «Not supported yet» с причиной.
6. В агенте меняются только ключ и модель: они переезжают в API & Models.
   Остальное во вкладке Agents не трогаем.

## Реестр AI-фич

Порядок строк — как в таблице.

| ID | Подпись в UI | Режим | Кто вызывает сейчас |
|---|---|---|---|
| `dropFast` | Drop Fast | real-time | `TranscriptionSessionFactory` из Drop, режим fast |
| `dropSmart` | Drop Smart | real-time | то же, режим smart |
| `dropSmartCleanup` | Drop Smart cleanup | LLM | `PostProcessor` → `DirectLLMRouteResolver` |
| `meetings` | Meetings | recorded | `MeetingBYOKProcessor` |
| `meetingNotes` | Meeting notes | LLM | `MeetingBYOKProcessor.generateNoteMarkdown` |
| `agent` | Agent | LLM with tools | `OpenCodeProvider` (`--model openrouter/<id>`) |
| `agentVoice` | Agent voice | real-time | `makeStreamingSession(resilient: false)` для голоса агента |
| `voiceSearch` | Voice search | real-time | `makeStreamingSession(resilient: false)` для поиска Google |
| `translation` | Translation | LLM | `TranslationService`: только текстовый перевод |
| `subtitlesAudio` | Subtitles audio | real-time | `LiveSubtitleModel`: только системный звук |
| `subtitlesTranslation` | Subtitles translation | LLM | `LiveSubtitleModel`: перевод финальных фраз; в UI вместе с Speech в группе Subtitles |

У Subtitles два независимых выбора: Speech и LLM. При обновлении конфигурации
версии 1 с настроенным `subtitlesAudio` текущий `translation` один раз копируется
в `subtitlesTranslation`, включая выбранного провайдера; версия миграции становится
2. Уже заданный маршрут сохраняется. Если субтитры не настроены или общего LLM
нет, новый выбор остаётся пустым. Последующие изменения Translation и очистка
Subtitles LLM независимы; восстановления через другой маршрут в runtime нет.
Частично нечитаемые документы не переписываются при запуске. До первого
изменения прежняя LLM настроенных субтитров доступна через разделение v1 в памяти
с тем же аккаунтом, моделью и провайдером. Их первое явное
редактирование сохраняет исходную копию и разделяет маршруты до применения
изменения, поэтому очистка модели или удаление сервера не отменяются при запуске.
Если отдельный маршрут субтитров записан, но не читается, он остаётся недоступным:
это не отсутствие старой настройки, допускающее перенос из Translation.

Запасные пути отдельных строк не получают:

- **Запасная расшифровка Drop** (batch rung, Retry на «Couldn't deliver»,
  recorder fallback) идёт к провайдеру той фичи, что вела этот Drop (Fast или
  Smart). Модель берётся из проверенной recorded-модели этого провайдера (см.
  «Проверенные модели»).
- **Batch-голос агента** идёт к провайдеру `agentVoice` по тому же правилу.
- Если у провайдера нет проверенной recorded-модели, запасной путь недоступен
  (как сейчас при отсутствии ключа). К другому провайдеру он не идёт никогда.

### Режим recorded у митингов

Сейчас митинги расшифровываются по-разному:

- Soniox — через файловый API: async-модель и спикеры (`SonioxMeetingTranscriber`);
- Deepgram, ElevenLabs и свой сервер — запись кусками по 30 с прогоняется через
  их real-time адаптер (`MeetingBYOKTranscriber`).

В v1 пайплайны митингов не меняем. Поэтому список моделей для `meetings` зависит
от провайдера: у Soniox — его async-модели, у остальных — их real-time модели.
Подпись «recorded» описывает фичу (она работает с готовой записью), а не тип модели.

Перевод Deepgram, ElevenLabs и своего сервера на пакетный API со спикерами — это
отдельное предложение на потом, не v1.

## API hints

Внизу раздела, после блока Models, расположена ссылка **API hints**, доступная и без
сохранённых ключей. Она открывает отдельный лист с четырьмя карточками:
Deepgram, ElevenLabs, OpenRouter и Claude Max. В карточках — значок провайдера,
крупная сумма или лимит, период, короткие условия и официальная ссылка.
Для Claude Max явно указан платный план. Внизу всегда видны дата проверки,
**Add API key** и **Done**; Return и Escape закрывают лист. Лампочки и
раскрывающегося блока нет. Просмотр не делает сетевых запросов и не меняет
модели или ключи. **Add API key** открывает существующую форму. Подробности и источники:
[API hints](../../.project-docs/decisions/2026-10-19-api-hints.md).

## Блок API keys

**Провайдеры v1:**

- Soniox, Deepgram, ElevenLabs — транскрибация;
- OpenRouter — LLM;
- OpenAI-compatible server — свой сервер: base URL и необязательный ключ. Таких
  серверов может быть несколько.

Несколько серверов нужны, чтобы миграция ничего не потеряла: сейчас real-time
сервер (`selfHostedBaseURL`) и LLM-сервер (`customLLMBaseURL`) настраиваются
отдельно и могут быть разными машинами.

**Вид.** Ряд чипов: имя провайдера и точка статуса. Последний чип — «Add key».
Провайдеров без ключа в ряду нет.

- Зелёная точка — ключ работает.
- Жёлтая — ключ рабочий, но права урезаны (провайдер не отдаёт ему список
  моделей или данные аккаунта), либо проверить сейчас не удалось, например нет
  сети. Строки фич на таком ключе значка не получают.
- Красная — ключ не принят или кончились деньги.

**Клик по чипу** открывает поповер:

- статус текстом и время последней проверки;
- Replace key;
- Remove. Перед удалением показать, какие фичи останутся без модели.

**Add key:** выбор провайдера из ещё не добавленных → поле ключа (secure) →
Save → проверка ключа → появляется чип. Для сервера: base URL, ключ (необязателен)
и короткое имя.

**После добавления ключа** Whytap предлагает назначить его фичам, но сам этого не
делает. Открывается окно «Use Soniox for»:

- в списке фичи в статусе Not set, которые этот провайдер умеет;
- у каждой — галочка и рекомендуемая модель из вшитого реестра;
- «Use» назначает отмеченное, «Not now» ничего не меняет;
- фичи, уже работающие на другом провайдере, в окне не показываются.

Если ключи есть, а фичи в Not set (новый пользователь или пользователь Apple
Silicon без сохранённого выбора), над блоком Models висит строка «N features have
no model · Set up». Она открывает то же окно.

Назначение остаётся явным выбором пользователя. Поэтому не нарушаются ни
инвариант 3, ни решение `2026-10-18-remove-local-models` (не включать маршрут
только потому, что ключ сохранён).

**Хранение:**

- Keychain, те же service и accounts, что сейчас: `byok.<provider>.api_key`,
  `byok.openrouter.llm_api_key`, `byok.custom_llm.api_key`. Переносить ключи не нужно.
- Для дополнительных серверов — новые accounts. Схему выбирает исполнитель.
  Добавить их в `CredentialMigration.migratedAccounts`, если этого требует логика
  миграции.
- После сохранения значение ключа на экран не возвращается.

**Проверка ключа** — бесплатный запрос к провайдеру (см. «Факты о провайдерах»).
Ответы раскладываются так:

- **Красный:** ключ не принят (401 с кодом неверного ключа) или кончились деньги (402).
- **Жёлтый «Limited key»:** ключ принят, но права ключа запрещают этот запрос.
  Примеры: Soniox 403 `permission_denied`, Deepgram 401/403
  `INSUFFICIENT_PERMISSIONS`, ElevenLabs 403 `insufficient_permissions`. Список
  моделей тогда берётся из вшитого реестра и «Other model ID…».
- **Жёлтый:** нет сети или ответ 5xx. Сохраняется последний известный статус.

Когда идёт проверка:

- при сохранении ключа;
- при открытии вкладки, если результат старше суток, — только бесплатными
  запросами;
- по клику на чип.

Платная STT-проба ради проверки ключа (она нужна для урезанного ключа ElevenLabs)
делается только при сохранении ключа и по «Check now».

**Удаление ключа.** Фичи на этом провайдере становятся «Not set». На другого
провайдера они не переключаются.

## Блок Models

**Строка:** название фичи, рядом мелко режим, и одна выпадашка «Provider · model-id».
Статус в строке показывается только при проблеме:

| Статус | Когда |
|---|---|
| Not verified | модель введена через «Other model ID…» или сменилась версия адаптера, а пробы с новой версией ещё не было |
| Deprecated alias | провайдер сообщает, что ID — псевдоним другой модели (у Soniox поле `aliased_model_id`). Так будет со `stt-rt-v4` у Максима: «alias of stt-rt-v5», кнопка «Switch to stt-rt-v5» |
| Removed by provider | выбранной модели больше нет в каталоге провайдера |
| Not supported yet | модель не прошла проверку; рядом причина |
| Key problem | ключ провайдера не принят или кончились деньги (красная точка) |
| Not set | модель не выбрана |

Значок появляется только при признаке проблемы. Сам факт, что пробы не было,
признаком не считается (см. «Проверка моделей»). Если одна проблема у нескольких
строк сразу (например, `stt-rt-v4` в четырёх real-time фичах), над блоком
показывается одна строка с общим действием: «Switch 4 features to stt-rt-v5».

У «Not verified» и «Removed by provider» есть действие «Check now» или «Choose model».

**Выпадашка:**

- Группы по провайдерам. Показываются только провайдеры с ключом, которые умеют
  режим фичи.
- Внутри группы — проверенные модели (у выбранной галочка) и новые с подписью
  «checked when picked».
- В конце серым одной строкой: «Not supported yet: <модели> (<причина>)».
- Внизу:
  - «Refresh models»;
  - «Other model ID…» — для провайдеров без списка моделей в API и для своих
    серверов. Введённый ID проходит ту же проверку, что и новая модель.
- Если подходящих провайдеров нет: «Add a key for <провайдеры, которые умеют этот
  режим>» со ссылкой на Add key.

**Выбор новой модели** запускает проверку, в строке крутится спиннер.

- Прошла — модель выбрана и стала проверенной.
- Не прошла — остаётся прежняя модель, строка показывает причину.

## Проверка моделей (вариант B)

Состояние считается для четвёрки: фича (через её режим), провайдер, модель и
версия адаптера.

**Версия адаптера** — константа в коде для каждой пары «провайдер × режим».
Разработчик поднимает её, когда меняется формат запроса к провайдеру. Обычный
релиз Whytap её не меняет, поэтому пройденные пробы переживают обновления.

1. **Verified** — выполняется одно из условий:
   - модель есть во вшитом реестре проверенных моделей;
   - модель прошла пробу на этом Mac при текущей версии адаптера;
   - модель была выбрана до миграции, и с тех пор не появилось признаков
     проблемы. Признаки — снята, псевдоним, истекает или отказ в рантайме.
2. **New** — модель есть в каталоге провайдера, данные каталога не противоречат
   требованиям режима, но пробы ещё не было.
3. **Not supported yet: причина.** Возможные причины:
   - по каталогу модели не хватает требования режима;
   - проба упала;
   - провайдер подаёт модель через протокол или endpoint, которого адаптер Whytap
     не знает.
4. **Removed** — выбранной модели больше нет в каталоге.

**Требования режимов:**

- **real-time** — потоковая расшифровка с частичными результатами по протоколу,
  который знает адаптер провайдера в Whytap. Поддержка языка и словаря терминов
  желательна, но не обязательна.
- **recorded** — путь записи для этого провайдера из раздела «Режим recorded у
  митингов». Спикеры желательны: модель со спикерами помечается.
- **LLM** (`dropSmartCleanup`):
  - chat/completions с текстом на выходе;
  - reasoning можно выключить или снизить: работает нынешняя политика Smart
    (`OpenRouterReasoningPolicy`, «lowest supported effort or off»);
  - скорость — подсказка, а не фильтр.
- **LLM** (`meetingNotes`) — chat/completions с текстом на выходе и контекстом не
  меньше N токенов. N подбирает исполнитель; ориентир — двухчасовой митинг
  плюс промпт.
- **LLM with tools** (`agent`) — по каталогу OpenRouter поддерживаются tools,
  контекст не меньше M, которого хватает OpenCode. Проба делается с одним
  фиктивным инструментом. Сам OpenCode модели без инструментов не отсекает,
  поэтому эта проверка — единственная защита. При передаче модели в OpenCode
  заполнять её возможности и лимиты из каталога (см. «Факты о провайдерах →
  OpenCode»).

**Проба:**

- Только синтетические данные: вшитый короткий клип речи на 1–2 с, тишина или
  минимальный текстовый запрос того же формата, что у фичи. Аудио и текст
  пользователя в пробу не попадают никогда.
- Идёт только к провайдеру, ключ которого добавил пользователь (инвариант 1).
- Стоит доли цента. Пробовать модель при каждом открытии вкладки нельзя: только
  при выборе новой модели и по «Check now».
- Результат кэшируется по провайдеру, модели, режиму и версии адаптера.
  Обновление Whytap без смены версии адаптера пробы не сбрасывает. Если версия
  сменилась, модели вне вшитого реестра получают «Not verified · Check now» и
  перепроверяются по кнопке или при следующем выборе.

**Каталог:**

- Источник — API провайдера (см. «Факты о провайдерах»). Если у провайдера нет
  списка моделей для режима, каталог состоит из вшитого реестра и «Other model ID…».
- Обновляется при открытии вкладки, если кэш старше суток (порог — на усмотрение
  исполнителя); при сохранении ключа; по «Refresh models».
- Без сети показывается кэш с пометкой «Couldn't refresh». Выбранные модели
  продолжают работать.

**Вшитый реестр проверенных моделей:**

- выходит с релизами Whytap;
- на каждую модель в нём есть тесты адаптера;
- по режиму в нём указан рекомендуемый дефолт;
- для каждого провайдера указана recorded-модель для запасной расшифровки.
  Сейчас это `stt-async-v5` у Soniox, `scribe_v2` у ElevenLabs и та же модель,
  что в real-time, у Deepgram и своего сервера.

**Рантайм:**

- Фича читает свою модель из реестра при каждом вызове (как сейчас «route is
  read on every call»).
- Провайдер отверг модель — фича выдаёт понятную ошибку со ссылкой на
  API & Models. Модель и провайдер не подменяются.
- Модель не меняется молча никогда. Непроверенная сохранённая модель работает
  как сохранена, строка показывает «Not verified», решение принимает пользователь.

## Миграция (тихо, при первом запуске новой сборки)

Своя в каждом flavor: у prod и beta отдельные UserDefaults и Keychain-сервис.
Миграция идемпотентная и работает без сети.

**Ключи** остаются на месте. В блоке API keys появляются провайдеры, у которых в
Keychain есть непустой ключ.

**Модели фич:**

| Фичи | Откуда берётся модель |
|---|---|
| `dropFast`, `dropSmart`, `agentVoice`, `voiceSearch` | `selectedProvider` + `transcriptionModel(for:)`, включая сохранённую `stt-rt-v4` — без замены |
| `meetings` | тот же провайдер: у Soniox `stt-async-v5`, у остальных их real-time модель (как сейчас) |
| `dropSmartCleanup`, `meetingNotes` | `llmLevel`: `yourKey` → OpenRouter + `openRouterModel`; `custom` → запись сервера из `customLLMBaseURL` + `customLLMModel`; `nil` → Not set |
| `agent` | `agent.opencode.model` у OpenRouter; пусто → Not set |
| все real-time фичи при `transcriptionLevel == nil` | Not set — правила `SelfKeyPreferences.storedLevel` (retired Local, Apple Silicon) сохраняются |

Записи серверов получаются из `selfHostedBaseURL` (real-time и recorded) и
`customLLMBaseURL` (LLM).

Модели, выбранные до миграции, считаются рабочими: значка у них нет, пока не
появится признак проблемы. Это пометка в каталоге (снята, псевдоним, истекает)
или отказ провайдера в рантайме. Сразу после миграции у Максима будет одна такая
пометка: «Deprecated alias» на четырёх строках со `stt-rt-v4` и общая кнопка
переключения.

Старые ключи UserDefaults не удалять и не перезаписывать. Тогда откат на прошлую
сборку увидит настройки, какими они были до миграции.

## Вкладка Agents после изменений

- **Убрать** блок OpenRouter: поле ключа, Model ID, Find a model, Choose model,
  Refresh и подпись «shared with Models».
- **Вместо него** одна строка «Model: OpenRouter · <id>» и кнопка «Change in
  API & Models», которая открывает вкладку и подсвечивает строку Agent. Если
  модель не выбрана — «Choose a model in API & Models».
- **Без изменений:** Use Agent shortcuts, установка и обновление OpenCode, Allow
  agent actions, Save & connect / Disconnect. Save & connect больше не сохраняет
  ключ, только подключает.

## Остальное поведение

- **Drop без модели для текущего режима** (Fast или Smart) открывает API & Models
  на строке этой фичи. Сейчас он открывает Models. Режим и модель фиксируются на
  старте Drop.
- **Smart без `dropSmartCleanup`** — как сейчас: вставляется результат без LLM.
- **Митинг без модели** транскрибации или заметок — как сейчас: запись ждёт в
  staging. Текст `MeetingsCoordinator.processorNotConfiguredMessage` ведёт в
  API & Models.
- **Агент без модели** — сообщение «Choose a model in API & Models».
- **Иконки провайдера в острове** (`TranscriptionProviderBrand.currentDrop` и
  `currentDropCleanup`) берут провайдера той фичи, что сейчас работает.
- **Settings** по умолчанию открывается на API & Models.

## Не цели v1

- Прямые LLM-провайдеры OpenAI и Google. Реестр должен позволять
  добавить их позже без переделки UI.
- Anthropic — только для строки Agent (решение Максима 19.10.2026: тратить
  API-кредиты Anthropic через агента). Для Drop Smart cleanup и Meeting notes
  Anthropic в v1 не предлагается.
- Свой сервер для агента.
- Модели по проектам, учёт расходов и балансов, Case, окружения prod/dev.
- Другие изменения во вкладке Agents, в том числе «Update app copy».
- Общие ключи у Beta и prod: у Beta свой Keychain-сервис, так и остаётся.
- Пакетный API со спикерами для митингов у Deepgram, ElevenLabs и своего сервера.
- Региональные хосты Soniox (`api.eu|jp|in`) и ElevenLabs (data residency). Если
  ключ не принят, текст ошибки упоминает, что региональные ключи пока не
  поддерживаются.
- Починка передачи ключа в WebSocket Soniox — отдельная задача, срок до 15.01.2027.

## Анти-цели: это провал, даже если «работает»

- Аудио или текст ушли провайдеру, которого пользователь не выбрал для этой
  фичи, в том числе через запасной путь или пробу.
- Whytap сам сменил модель или провайдера.
- Экран показывает одну модель, а уходит другая.
- Интерфейс тяжелее макета: две выпадашки в строке или бейджи на каждой строке.
- После обновления нужно заново вводить ключи или выбирать модели.
- Без сети фичи перестают работать из-за недоступного каталога.
- Ключ, транскрипт или промпт попадают в `os_log`, UserDefaults или файлы.

## Решения, принятые без Максима (на проверку)

1. Голос агента и голосовой поиск — отдельные строки (`agentVoice`, `voiceSearch`).
   При миграции у них та же модель, что у Drop.
2. Запасная расшифровка Drop и batch-голос агента идут к провайдеру своей фичи с
   recorded-моделью из вшитого реестра. К другому провайдеру — никогда.
3. Пайплайны митингов в v1 не меняются. Поэтому список моделей для Meetings
   зависит от провайдера: у Soniox async-модели, у остальных real-time.
4. Своих серверов может быть несколько: иначе миграция теряет второй сервер.
5. Старые ключи UserDefaults после миграции не трогаются, чтобы работал откат.
6. Модель никогда не меняется сама. Устаревший псевдоним (`stt-rt-v4`) только
   помечается, и рядом кнопка переключения.
7. Пробы — только на синтетических данных и только при выборе модели или по
   «Check now».
8. Regional-ключи Soniox и ElevenLabs — не в v1.
9. После добавления ключа Whytap предлагает назначить его пустым фичам, но сам
   не назначает.
10. Значок у строки появляется только при признаке проблемы. Модели, выбранные
    до миграции, и пробы, пройденные при текущей версии адаптера, значка не
    дают. Обычное обновление Whytap пробы не сбрасывает.
11. Ключ с урезанными правами помечается жёлтым, а не красным. При открытии
    вкладки — только бесплатные проверки.

## Факты о провайдерах

Собрано 19.10.2026 по официальной документации, OpenAPI и исходникам, без ключей.
Ответы эндпоинтов, которым нужен ключ, описаны по документации и вживую не
проверены. Два факта про Soniox (псевдонимы и передача ключа) перепроверены
отдельно по документации Soniox. Полная выжимка и
скачанные спецификации — `brief.md` в scratchpad сессии от 19.10.

Ни у одного провайдера каталога не хватает, чтобы решить «подходит ли модель».
Поэтому решение складывается из каталога, вшитого реестра и пробы.

**Soniox**

- Каталог: `GET https://api.soniox.com/v1/models`, `Authorization: Bearer <key>`.
  Поля модели: `id`, `aliased_model_id`, `transcription_mode` (`real_time` | `async`),
  `languages[]`, флаги `supports_*`. Флага спикеров и даты снятия нет; спикеры —
  параметр запроса `enable_speaker_diarization`.
  https://soniox.com/docs/openapi.yaml
- Ключ: тот же бесплатный `GET /v1/models`.
  - 401 `unauthenticated` — ключ не принят. На американском хосте это может
    значить и ключ другого региона: `api.eu|jp|in.soniox.com`.
  - 403 `permission_denied` — ключ рабочий, но у него нет права «Model listing».
  - 402 `organization_balance_exhausted` — кончились деньги.

  https://soniox.com/docs/api-reference/errors.mdx
- Модели: `stt-rt-v5` и `stt-async-v5`. `-v4` — устаревшие псевдонимы v5,
  `-v3` устарели. https://soniox.com/docs/stt/models.mdx (перепроверено)
- WebSocket: ключ передаётся при подключении — заголовком `Authorization: Bearer`
  или через список протоколов. Поле `api_key` в первом сообщении устарело, а с
  15.01.2027 соединение с ключом только там будет отклонено. Whytap сейчас шлёт
  ключ именно так (`SonioxBYOKAdapter.swift:70`). Проба в этой спеке должна
  использовать заголовок. Починка адаптера — отдельная задача, её нужно влить до
  15.01.2027. https://soniox.com/docs/api-reference/stt/websocket-api.mdx (перепроверено)
- Проба: 1 с аудио стоит около $0.00003 (real-time $0.12/ч, async $0.10/ч).

**Deepgram**

- Каталог: `GET https://api.deepgram.com/v1/models`, ключ не нужен. В `stt[]`
  у каждой строки: `name`, `canonical_name`, `languages[]`, `streaming`, `batch`.
  Строки разбиты по языкам и версиям, их нужно склеивать по `canonical_name`.
  https://developers.deepgram.com/guides/fundamentals/model-metadata.md
- Flux (`flux-general-en`, `flux-general-multi`) в каталоге нет. Он работает
  только в real-time, через `/v2/listen`, и шлёт события `TurnInfo` вместо
  `Results`. Адаптер Whytap этого не умеет, поэтому Flux — «Not supported yet:
  needs Deepgram's v2 streaming API».
  https://developers.deepgram.com/docs/flux/nova-3-migration.md
- Ключ: бесплатный `GET /v1/projects`, `Authorization: Token <key>`.
  - 401 `INVALID_AUTH` — ключ не принят.
  - 401 `INSUFFICIENT_PERMISSIONS` — не хватает прав.
  - 402 `ASR_PAYMENT_REQUIRED` — кончились деньги.

  https://developers.deepgram.com/docs/errors.md
- Спикеры: `diarize` устарел, вместо него `diarize_model`.
  https://developers.deepgram.com/docs/diarization.md

**ElevenLabs**

- `GET /v1/models` описывает модели озвучки, флагов STT в нём нет. Поэтому модели
  STT берутся из вшитого реестра: `scribe_v2_realtime` для real-time, `scribe_v2`
  для записи (`scribe_v1` устарела). Новые модели — через «Other model ID…» и пробу.
  https://elevenlabs.io/docs/overview/models.md
- Ключ: `GET /v1/user` (`xi-api-key`).
  - 401 `invalid_api_key` — ключ не принят.
  - 403 `insufficient_permissions` — ключ ограничен по правам. Ключ только для
    STT может получить отказ на `/user`, и это не значит, что он плохой. В этом
    случае ключ проверяется минимальной STT-пробой.
  - 402 `insufficient_credits` — кончились деньги.

  Аккаунты с хранением данных в регионе работают на других хостах, это не v1.
  https://elevenlabs.io/docs/eleven-api/resources/errors.md
- Проба: пакетный запрос с WAV на 1 с стоит около $0.00006.

**OpenRouter**

- Каталог: `GET https://openrouter.ai/api/v1/models`, работает без ключа; `/models/user`
  с ключом учитывает настройки аккаунта.
  - Поля модели: `id`, `context_length`, `expiration_date`,
    `supported_parameters[]` (в том числе `tools`, `tool_choice`, `reasoning`,
    `max_tokens`, `temperature`), `architecture.output_modalities`,
    `top_provider.max_completion_tokens`, `reasoning{mandatory, supported_efforts}`.
  - Сервер умеет фильтровать сам: `supported_parameters=tools` (условия через И).
  - `GET /models/{author}/{slug}/endpoints` отдаёт параметры по каждому
    провайдеру-хосту.

  https://openrouter.ai/openapi.json, https://openrouter.ai/docs/guides/overview/models.md
- Подвохи:
  - `supported_parameters` — объединение по всем хостам модели. Без
    `provider.require_parameters: true` неподдерживаемые параметры молча
    отбрасываются.
  - Из списков фич нужно убрать `:batch`-варианты, псевдонимы `~…-latest`,
    роутеры с ценой −1 и модели не с текстовым выходом. Нынешний `openrouter/auto`
    для LLM-фич оставить, как сейчас.
  - Если у модели есть `expiration_date`, показывать предупреждение заранее.
  - Модели с `reasoning.mandatory` для `dropSmartCleanup` помечать «always reasons,
    slower» — это подсказка, не запрет.

  https://openrouter.ai/docs/guides/routing/provider-selection.md
- Ключ: `GET /api/v1/key`.
  - 401 — ключ не принят.
  - 402 `payment_required` — кончились деньги или лимит ключа.
  - 403 — сработал guardrail или бюджет ключа.

  https://openrouter.ai/docs/api/reference/errors-and-debugging.md
- Проба: `chat/completions` с `max_tokens: 16` (на 1 часть моделей падает, это не
  проверено), с параметрами только из `supported_parameters` и с
  `provider.require_parameters: true`. Для агента — с одним фиктивным
  инструментом. Стоит от $0.00001 до $0.001.

**Свой сервер (OpenAI-compatible)**

- `GET /v1/models` отдаёт только `id`, никаких возможностей. Возможности знают
  только «родные» эндпоинты: Ollama `POST /api/show` (`capabilities[]`), LM Studio
  `GET /api/v1/models` (`capabilities`), LiteLLM `/model/info`. В v1 хватает `id`
  и пробы, а разбор этих эндпоинтов можно добавить потом.
- Real-time протоколы у vLLM, OpenAI GA и Speaches отличаются (события и частота
  дискретизации). Что подходит, решает проба. Если не подошло — «Not supported
  yet: this server's realtime dialect».
  https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/speech_to_text/realtime/api_router.py

**OpenCode (агент)**

- OpenCode не отказывается от моделей без поддержки инструментов: поле
  `capabilities.toolcall` он не читает (v1.19.3). Поэтому отсекать такие модели
  для `agent` должна сама Whytap.
- Whytap объявляет выбранную модель в `OPENCODE_CONFIG_CONTENT` с пустым объектом
  (`OpenCodeEnvironment`, `"models": [normalized: [:]]`). По исходникам OpenCode,
  у объявленной так модели, которой нет в его снимке models.dev, `limit.context`
  становится 0, и это выключает автосжатие контекста. Поэтому при объявлении
  нужно заполнять `tool_call`, `reasoning`, `limit.context` и `limit.output` из
  каталога OpenRouter. На реальном OpenCode это не проверено — проверить при
  реализации.
  https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/provider/provider.ts
