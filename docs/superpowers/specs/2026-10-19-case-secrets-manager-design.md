# Case: локальный менеджер секретов с доступом для ИИ

Дата: 2026-10-19. Статус: черновик на согласование с Максимом.

Метки: **[Максим]** — решил Максим; **[моё]** — решение автора дизайна,
Максим может поправить; **[сборщик]** — оставлено на усмотрение сборщика.

## Зачем

Case — уже существующий инструмент в hover-панели острова: зашифрованное
хранилище ключей с Touch ID. Он должен стать менеджером секретов в духе
Doppler и подключаться к ИИ-ассистентам так, чтобы ИИ пользовался ключами,
не видя их значений.

Почему это важно: сейчас ИИ (Claude Code, Codex) берёт секреты из Doppler
командами вроде `doppler secrets get NETCUP_IP --plain`. Значение легко
попадает в переписку, а переписка уходит провайдерам моделей и в командный
recall-хаб. Case должен сделать так, чтобы у ИИ не было команды, которая
выдаёт значение.

## Цели

1. Проекты: встроенный неудаляемый **General** сверху, свои проекты рядом. **[Максим]**
2. ИИ видит проекты и имена ключей, но не значения. **[Максим]**
3. ИИ использует ключ через инструмент, не видя значения. **[Максим]**
4. Всё хранится локально и зашифровано. **[Максим]**
5. Доступ только у зарегистрированных приложений, у каждого режим
   Approve или Bypass; Bypass настраивается и для пары «приложение +
   проект». **[Максим]**
6. Собственное использование человеком (копирование в острове, команда в
   своём терминале) — через Touch ID. **[Максим]**

## Не цели (первая версия)

- Окружения (prod/dev/свои). Модель данных оставляет место, UI нет. **[Максим]**
- ИИ без терминала (чат Claude Desktop и т.п.). **[Максим]**
- Журнал использования ключей ИИ. **[Максим]**
- Запрос недостающего ключа от ИИ через остров. **[Максим]**
- Кнопка «Copy all» у проекта (убирается вместе с групповой). **[Максим]**
- Синхронизация между устройствами, облако, команда.
- HTTP-инструмент с плейсхолдерами `{{NAME}}` и списком разрешённых хостов
  (вариант для ИИ без терминала, на потом). **[моё]**

## Анти-цели (провал, даже если «работает»)

- Значение ключа оказалось в выводе инструмента, в MCP-ответе, в аргументах
  команды, в конфиге ИИ-клиента, в `os_log` или в репозитории.
- Миграция потеряла хоть один ключ существующего хранилища.
- Команды ИИ получили разрешения TCC самой Whytap (Accessibility, микрофон,
  Input Monitoring, запись звука).
- Незарегистрированное приложение получило ключи без вопроса.
- Запрос Approve перехватывает обычный набор текста, когда запроса нет.

## Модель угроз (честно)

Case защищает от **случайной** утечки значений в переписку и от доступа
незарегистрированных программ. Не защищает от ИИ, который **нарочно**
вытаскивает значение (перевернёт строку, запишет в файл и прочитает), и от
вредоносного кода под тем же пользователем — так же, как Doppler CLI и
`op run` у 1Password. Всё, что запускает зарегистрированный ИИ в своём
терминале (включая скрипты npm), действует с его правами.

## Данные

Схема хранилища v2 **[моё]**:

- `CaseProject { id, name, description, createdAt, updatedAt }`. General
  имеет фиксированный id, не удаляется, переименовывать нельзя. **[моё]**
- `CaseSecret` получает `projectID` вместо `groupID`. Имя уникально внутри
  проекта; одно имя может быть в разных проектах. **[Максим]**
- У проекта и у ключа есть необязательное описание (обычный текст, не
  секрет; ИИ его видит — оно помогает выбрать нужный ключ). Редактируется
  карандашом. **[Максим]**, длина и вид в UI **[сборщик]**.
- Значения по-прежнему отдельно (`CaseSecretValue`). Место под окружения:
  будущий необязательный `environmentID` у значения. **[моё]**
- Регистрации приложений и режимы — в том же зашифрованном хранилище. **[моё]**
- Имена: `A–Z`, `0–9`, `_`, не начинаются с цифры (правило Doppler; сейчас
  цифра в начале разрешена — при миграции такие имена получают префикс `_`
  или похожее исправление, без потери ключа). **[сборщик]** в деталях.
- Имя проекта: до 48 символов, как у групп сейчас. **[моё]**

Миграция v1 → v2 **[Максим]**: ключи без группы → General; каждая группа →
проект с тем же именем. Сохраняются все существующие гарантии
(`docs/bugs/2026-10-08-case-vault-never-lost.md`): `.bak` перед записью,
reset откладывает файл, `needsNewerApp` для новой схемы. Старая сборка,
открыв v2, должна видеть `needsNewerApp`, а не предложение сбросить.

## Интерфейс в острове

Макеты: вариант C (`.superpowers/brainstorm/…/case-layout-v2.html`,
`case-ai-connect-v2.html` — во временной папке сессии, не в репо).

Экран ключей **[Максим]**:
- Один список, проекты сворачиваются. General раскрыт сверху.
- Сверху поле «Имя ключа или поиск» и «+ Проект». Поиск идёт по всем проектам. **[моё]**
- У ключа три кнопки-иконки: карандаш (имя или значение), копировать,
  удалить. **[Максим]**
- У проекта: карандаш (переименовать) и удаление; у General удаления нет. **[моё]**
- Удаление проекта удаляет его ключи, после подтверждения. **[Максим]**
- Новый ключ — строка «+ Ключ в <проект>» внутри раскрытого проекта. **[моё]**
- Перенос ключа между проектами — перетаскиванием (как сейчас ключи
  собираются в группы). Конфликт имён в целевом проекте — отказ с
  подсказкой. **[моё]**
- Внизу строка «ИИ: <зарегистрированные>» и «Подключить ›». **[моё]**
- Разблокировка, 15 минут бездействия, лимиты размера значения — как сейчас.

Экран «Доступ приложений» **[Максим]** по смыслу, раскладка **[моё]**:
- Список зарегистрированных приложений. У каждого переключатель
  Approve / Bypass и, по желанию, отдельный режим для конкретного проекта
  («как у приложения» по умолчанию).
- «+ Зарегистрировать приложение»: быстрые варианты для найденных Claude
  Code, Codex, Cursor, OpenCode (встроенный агент) и выбор любой программы. **[моё]**
- Новое приложение по умолчанию в Approve. **[моё]**
- Регистрация и включение Bypass — Touch ID; переход на Approve и удаление
  регистрации — без него, доступ закрывается сразу. **[моё]**
- Регистрация ИИ-клиента также добавляет Case MCP в его настройки
  (`claude mcp add -s user …`, `codex mcp add …`, `~/.cursor/mcp.json`,
  конфиг встроенного OpenCode). Секретов в этих настройках нет.
  Удаление регистрации убирает запись. **[моё]**

Запрос Approve (в острове) **[Максим]**:
- Лаконичное, красивое окно в стиле острова: приложение, проект, имена
  ключей, сама команда (одна строка, обрезанная с многоточием).
- Две кнопки: «Отклонить» и «Разрешить», с подсказками клавиш Y и N
  (через `HotkeyHintView`, строка в Help).
- **Y / N перехватываются на любой раскладке** — по физической клавише
  (keycode `kVK_ANSI_Y` / `kVK_ANSI_N`), то есть «н» и «т» в русской
  раскладке тоже работают. Esc = отклонить. **[Максим]**
- Перехват клавиш только пока запрос на экране; остальные клавиши не
  трогаются; ничего не логируется. Риск: человек печатает в редакторе и
  случайно нажмёт Y — смягчение **[сборщик]** (например, короткая задержка
  ~300 мс после появления, когда клавиши ещё не принимаются).
- Кнопку «Разрешить на 15 мин» из макета убрали ради лаконичности. **[моё]**
- Таймаут без ответа = отклонено (около 60 с). **[сборщик]**
- Несколько запросов подряд — очередь, по одному на экране. **[сборщик]**

Найдено попутно: в настройках Whytap уже есть вкладка Projects (папки для
поиска по коду). Чтобы не путать с проектами Case, переименовать её,
например, в «Папки проектов» — **предложение**, не делать без «да» Максима.

## Коннектор

Образец: `doppler run` для запуска и MCP-сервер 1Password Environments,
который по задумке отдаёт только имена (проверено по их документации).
Doppler, по их коду, отдаёт значения прямо в MCP-ответе — так не делаем.

Состав **[моё]**:

1. **CLI `whytap`** — отдельный исполняемый файл внутри Whytap.app
   (новая SwiftPM-цель), ссылка в PATH ставится при регистрации первого
   приложения (например, `~/.local/bin/whytap`). Имя `case` невозможно:
   это зарезервированное слово zsh/bash (проверено). Имя `whytap` на этом
   маке свободно (проверено).
   - `whytap case ls [-p проект]` — проекты и имена ключей с описаниями. **[Максим]**
   - `whytap case run [-p <проект>] [--only A,B] '<команда>'` — команда
     выполняется через `/bin/sh -c`, значения кладутся **только в
     переменные окружения** дочернего процесса. Аргументы видны любой
     программе пользователя через `ps`, окружение — нет (проверено на этом
     маке).
   - Вывод маскируется: точное значение, base64 (три сдвига, обычный и
     url-safe), hex (оба регистра), URL- и JSON-экранирование, многострочные
     значения целиком и построчно; буфер на стыке кусков вывода. Список —
     как у раннера GitHub Actions плюс hex. Минимальная длина значения для
     маскировки — **[сборщик]**; короткие значения в UI помечаются как «не
     скрываются в выводе».
   - Ключ можно запросить по имени без проекта (`--only OPENAI_API_KEY`).
     Имя есть в одном проекте — берётся оттуда. Есть в нескольких — Case
     ничего не запускает и возвращает ИИ список этих проектов с
     описаниями (код выхода ненулевой); ИИ сам выбирает проект по
     описаниям и повторяет запрос с `-p`, а если не уверен — спрашивает
     пользователя в своей переписке. Это правило записано в `instructions`
     MCP-сервера и в тексте ошибки. Окно в острове при этом не появляется. **[Максим]**
     General автоматически к проекту не подмешивается. **[Максим]**
   - Никакой команды, которая печатает значение ИИ. Для человека в своём
     терминале — тоже не делаем в первой версии (копирование есть в острове). **[моё]**
   - Маскировка через каналы снимает TTY у команды; для команды из
     собственного терминала человека можно использовать псевдотерминал —
     **[сборщик]**. MCP-канал маскировкой не оборачивается никогда (у
     1Password это ломает MCP).
2. **MCP-сервер** `whytap case mcp` (stdio): инструменты
   `case_list_projects`, `case_list_keys(project)` — только имена и
   описания; в
   `instructions` объяснено, как запускать `whytap case run` (одинарные
   кавычки, `$ИМЯ`). Инструмента «выполни команду» нет: команды идут через
   терминал самого ИИ, чтобы работали его песочница и правила разрешений. **[моё]**
3. **Брокер в приложении**: Unix-сокет в Application Support (папка 0700).
   Приложение проверяет подключившийся процесс по audit token
   (`LOCAL_PEERTOKEN` → `SecCodeCopyGuestWithAttributes` с
   `kSecGuestAttributeAudit`): это должен быть именно вложенный CLI из этой
   же сборки Whytap (сверка cdhash с файлом в бандле — работает и при
   ad-hoc подписи). Только после этого отдаёт значения. XPC вместо сокета —
   на усмотрение сборщика.
4. **Кто спрашивает.** Брокер идёт по цепочке родительских процессов CLI и
   ищет зарегистрированное приложение: Claude Code и Codex — по Developer ID
   (Anthropic `Q6L2SF6YDW`, `com.anthropic.claude-code`; OpenAI
   `2DC432GLL2`, `codex` — проверено на этом маке), остальные — по пути к
   программе (OpenCode из npm подписан ad-hoc). Встроенный OpenCode Whytap
   запускает сама. Проверена цепочка только для Claude Code из Claude.app:
   `zsh ← claude ← disclaimer ← Claude.app`; у Codex и Cursor — проверить
   при сборке.
   - Найдено зарегистрированное приложение → его режим для проекта:
     Bypass — сразу; Approve — запрос в острове.
   - Найдено известное, но незарегистрированное ИИ-приложение → отказ с
     подсказкой «зарегистрируй в Case».
   - Ничего не найдено (человек в Terminal/iTerm) → Touch ID.
   Токенов и секретов в конфигах ИИ нет.
5. **Процесс запускает CLI, а не приложение**, чтобы команда не
   унаследовала TCC-разрешения Whytap.
6. Whytap не запущена → CLI запускает её в фоне и ждёт сокет несколько
   секунд, иначе понятная ошибка. **[сборщик]** в деталях.
7. Песочницы ИИ: Claude Code с песочницей должен разрешить сокет Case
   (`sandbox.network.allowUnixSockets`, настройка существует — проверено по
   бинарнику); регистрация добавляет путь сокета, если песочница включена.
   Codex в режиме без сети сокет не откроет — CLI сообщает понятно. **[моё]**
8. Bypass-доступ работает, пока Whytap запущена и ключ из Keychain
   доступен (после первого входа в систему), без Touch ID. **[моё]**
9. Имена ключей (`ls`, MCP-инструменты списка) зарегистрированное
   приложение получает без запроса Approve, в любом режиме; Approve
   спрашивает только перед `run`. Незарегистрированное приложение не
   получает и имён. **[моё]**
10. Регистрация — на всё приложение целиком. Если у приложения общий
    терминал для человека и агента (Cursor), команды человека в этом
    терминале тоже идут по режиму приложения, а не через Touch ID. Это
    осознанный риск для Bypass: подсказка рядом с переключателем. Для
    Claude Code это верно и так: команды через `!` попадают в переписку. **[моё]**
11. Codex: конфиг его песочницы при регистрации не трогаем. В режиме без
    сети сокет закрыт, но Codex по умолчанию просит разрешения выполнить
    такую команду вне песочницы — тогда Case работает. (В
    `~/.codex/config.toml` Максима режим песочницы не задан — проверено.) **[моё]**
12. Несколько сборок: у каждого варианта (prod/beta/dev) свои хранилище,
    Keychain и сокет. Ссылку `~/.local/bin/whytap` ставит и держит только
    prod `/Applications/Whytap.app`; beta и dev ставят `whytap-beta` /
    `whytap-dev`. Регистрации приложений — свои в каждом варианте. **[моё]**

## Ограничения проекта

- Swift + SwiftUI + AppKit, SwiftPM; новая исполняемая цель для CLI,
  её нужно добавить в `scripts/dev-run.sh` и сборку DMG и подписать.
- Инварианты Whytap: никаких серверов Whytap и телеметрии; ключи и
  содержимое никогда не попадают в `os_log`
  (`LocalPathLoggingInvariantTests`); сохраняются bundle ID, Keychain
  service и пути Application Support; GitHub Actions выключены.
- Сборки сообщества подписаны ad-hoc, без Developer ID — проверка
  подписи CLI не может опираться на Team ID самой Whytap.
- Хоткей Y/N — по правилам `docs/hotkey.md`.
- После изменений обновить `CLAUDE.md` (архитектура, разрешения),
  `docs/customization/local-data.md`, `docs/privacy.md`, `docs/hotkey.md`,
  decision-doc с `// WHY:`.
