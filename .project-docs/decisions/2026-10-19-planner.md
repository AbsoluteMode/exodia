## Context

The user requested a local To-do list, then extended it with Exodia's own
calendar and a common view of Google, Apple, Outlook, Teams and Zoom calendars.
They selected direct provider connections inside Exodia rather than requiring
Google, Outlook and Zoom to be registered in macOS first.

## Alternatives

- Use only macOS calendar accounts through EventKit: fewer provider integrations,
  but does not satisfy the selected direct Google/Microsoft/Zoom connection flow.
- Add an Exodia synchronization backend: not selected; conflicts with the
  application's existing no-owned-backend boundary.

## Decision

Use catalog/search actions To-do and Calendar to open the same native Planner
window, preserving existing tool layouts. Keep local task/event data in an
atomic private archive, and keep provider credentials in Keychain. Use EventKit
for calendars available on the Mac; use direct browser OAuth with PKCE for
Google Calendar, Microsoft Graph and Zoom Calendar Service.

The implemented first version edits local events and reads external calendars.
Remote recurrence is expanded within the visible range by the provider. It
refreshes while the calendar view is visible, handles per-account failure, and
collapses copies only when external UID and occurrence boundaries match.

## Rationale

A common native window provides enough space for the month and daily agenda,
while the island remains the entry point. The local calendar and task list work
without provider registration or network access. Direct native OAuth avoids
introducing an application backend or embedding a confidential server secret.
External data is never copied into the user's local Exodia calendar automatically.

## Sources

The user requirement and implementation entry points are listed in frontmatter.
[The guide](../../docs/planner.md) records the exact provider contracts and setup
references checked during implementation.

## Comments and objections

No user objection was recorded. The read-only external-event scope is the
implementation's initial boundary, not a user request to prohibit future editing.

## Resolution

The source implements local tasks/events and native/direct calendar adapters.
It supplies no shared production OAuth app registrations. Live provider consent,
account compatibility and installed-app interaction remain separate acceptance
steps; synthetic tests do not establish those results.

## Consequences

Google, Microsoft and Zoom require registered public OAuth clients before live
sign-in. Zoom Calendar Service differs from a Zoom client's linked Google or
Microsoft calendar; the latter uses its actual provider connection. Teams links
arrive from Outlook events. The local archive is a new data store; integration
with concurrent encrypted-backup work must be reconciled before claiming
Planner content is covered by that feature.
